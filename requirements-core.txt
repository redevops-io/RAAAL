# --- The Discovery -> Mission boundary contract ---
# Owned by neither runtime, so pinned to a tag rather than a branch: a mutable
# ref can be rebased under a consumer, which is the fragility this project
# criticised in mission-sdk's bare-commit pin. Bump deliberately; a contract
# that moves silently is not a contract.
runtime-contracts @ git+https://github.com/redevops-io/runtime-contracts.git@v0.3.0
# `discovery-runtime` is deliberately absent here and installed from
# `vendor/discovery-runtime` by the Dockerfile instead.
#
# Two reasons, and the first is that the other way does not work: the
# repository is private, `pip` shells out to `git clone` over https, and a
# build with no credentials fails with "could not read Username for
# 'https://github.com'". The Dockerfile in git was not buildable at all, which
# is the second time this file has carried a git dependency nothing had ever
# built from.
#
# The second reason is better. Installing the submodule installs exactly the
# code this suite ran against, byte for byte, rather than re-fetching a tag
# that could in principle be moved. `runtime-contracts` stays a tag fetch
# because it is public and because the runtime declares which version it was
# released against — see tests/test_image_pins_the_runtime_it_was_tested_
# against.py, which holds the two in step.

# --- The Mission Runtime, for the cross-runtime replay gate ---
#
# **Not in the serving image.** `agentic-os@v0.2.3` pins
# `runtime-contracts@v0.2.2` and Quantify pins `v0.2.4`, so a build that
# installs both is unsatisfiable — `ResolutionImpossible`, and the reason this
# image could not be produced at all. It is in `requirements.txt`, where the
# cross-runtime replay gate that uses it runs.
#
# Removing it rather than loosening a pin, because the serving API does not
# use it: an import-graph walk from `src/api.py` reaches no module under
# `src/agentic/` and no `agentic_os` import at all. Only `src/agentic/` touches
# it, and nothing on the request path touches `src/agentic/`.
#
# `tests/test_serving_image_closure.py` asserts that, so the day the API does
# reach it the conflict has to be resolved rather than rediscovered by a
# failed build.
#
# Tag-pinned there for the same reason as the contracts above. Same licence
# family (AGPL-3.0-or-later WITH Commons-Clause), which is what made the
# import legal: see docs/Migration.md §6.6.
# OIDC token verification. The crypto extra brings the RSA
# backend PyJWT needs for RS256 — the algorithm Zitadel signs
# with. Verification is not hand-rolled here: parsing a JWT is
# easy and verifying one correctly is not, and the failure mode
# of getting it slightly wrong is an accepted forgery.
pyjwt[crypto]>=2.8

# Market conventions, so they are named rather than reasoned out.

# prints about itself. A convention library that did not reach production
# would be the same mistake with a different name.
